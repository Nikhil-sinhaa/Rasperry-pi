## Assets

Private uploads; extracted text; chunk text; embedding vectors; user questions;
model prompts/responses; source filenames/page metadata; cited quotes; transient
chat history.

## Intended trust boundary

The browser, Streamlit app, Ollama HTTP API, model weights and embedding model are
expected to run on the same computer.  The application only accepts
`http://127.0.0.1`, `http://localhost`, or `http://[::1]` for Ollama and rejects
other hosts.  The Streamlit server binds to `127.0.0.1`.  Requests use a session
with inherited proxy environment variables disabled.  Embeddings and retrieval are
computed in the process using local vectors; prompts are posted to the local Ollama
API.  Streamlit usage statistics are disabled.  A socket-level egress guard
(`install_egress_guard` in `legal_triage/local_runtime.py`) prevents the Python
process from opening connections to non-loopback hosts at runtime.

## Data-flow controls in code

| Data | Processing | Persistence / network behaviour |
|---|---|---|
| PDF/TXT/DOCX bytes | `legal_triage/ingestion.py` | Read from in-memory upload; parser uses `BytesIO`; app does not write the document to disk |
| Extracted text and chunks | page-aware chunker | Kept in session index; not logged by project code |
| Embeddings | Ollama `/api/embed` over loopback | Generated by local model; vectors kept in process memory |
| User question and retrieved excerpts | `legal_triage/agent.py` | Sent only to configured loopback Ollama API; remote endpoint blocked by config validation and egress guard |
| Model output | JSON parser and grounding checks | Raw completion is not shown or logged; only findings with valid source IDs and verbatim quotes are displayed |
| Temporary session state | Streamlit session | Clear button drops app's document index and chat state; this is not a secure RAM wipe |

## Threats not solved

The following threats are **not addressed** by this application.  They are
documented here so judges and users can understand the actual scope:

- **Semantic entailment:** the grounding check proves a quote exists verbatim; it
  does not prove the claim follows logically from the quote.
- **Gemma correctness:** the model may hallucinate even with grounding checks.
- **Process memory encryption:** session state, embeddings and model context live
  in plaintext RAM.
- **OS swap / virtual memory:** the operating system can page any part of the
  Python process's address space (document text, chunk embeddings, model prompts)
  to the swap partition or swap file on disk.  This happens transparently and
  silently.  The application has no control over when or whether the OS pages
  memory.  Mitigations:
  - Disable swap before handling sensitive documents (`sudo swapoff -a` on
    Linux, or "Turn off" in macOS Virtual Memory settings — note: macOS does
    not support disabling swap).
  - On macOS, the swap file is encrypted with the FileVault key at rest; FileVault
    must be enabled for this protection to apply.
  - On Linux, use LUKS-encrypted swap.
  - The canary disk search (`scripts/canary_disk_search.sh`) searches common temp
    directories but **does not** search the swap partition.
  - This is a known, documented residual risk; do not claim it is mitigated.
- **Multi-user OS isolation:** the app does not isolate concurrent OS users from
  each other's session data.
- **Compromised packages / OS / runtime:** supply-chain attacks on transitive
  dependencies or the OS are outside scope.  See `evidence/dependency-review.md`
  for the direct-dependency vulnerability assessment.
- **Pillow (transitive dependency):** Streamlit pulls in Pillow as a transitive
  dependency; the version bundled with `streamlit==1.50.0` has known CVEs.  Our
  app does not expose Pillow's image-processing code paths to uploaded documents
  (PDF text extraction uses pypdf, not Pillow), and the app runs on loopback only.
  See `evidence/dependency-review.md` for the full assessment.
- **OCR:** scanned PDFs are not processed; the limitation is stated in the UI.
- **System-wide traffic inspection:** the egress guard covers the Python process
  only.  The Ollama *server* process must be isolated separately via
  `OLLAMA_NO_CLOUD=1` and `OLLAMA_HOST=127.0.0.1:11434`; see Reproducible
  evidence protocol below.
- **Making the host offline:** the application cannot prevent the OS or other
  processes from sending data; network-off must be verified by the operator.
- **Ollama desktop update checks:** the desktop app may phone home at launch;
  start Ollama from the CLI with `OLLAMA_NO_CLOUD=1` or document this
  connection explicitly.
- **Socket guard scope:** `install_egress_guard` patches `socket.socket.connect`.
  It does not cover `socket.socket.connect_ex`, UDP `sendto`, or DNS lookups
  made by the OS resolver.  Treat this as defence-in-depth alongside the
  network namespace / `pfctl` evidence; do not rely on it as the sole proof
  of network isolation.

## Reproducible evidence protocol

1. Record source commit hash and model tags; do not include private documents.
2. Pull weights and install dependencies during setup (internet required); then
   disable the network or disconnect Wi-Fi.
3. With networking disabled, start Ollama (`OLLAMA_NO_CLOUD=1 OLLAMA_HOST=127.0.0.1:11434 ollama serve`)
   and Streamlit locally.  Upload the included synthetic sample.  Ask a
   known-answer question, an absent-information question, a legal-verdict
   question, and a prompt-injection question.
4. Run `bash scripts/capture_network.sh` in a separate terminal while the demo
   runs.  Keep raw packet captures out of the public repo; save a redacted text
   summary to `evidence/network-monitor.txt`.
5. Run `bash scripts/offline_proof.sh` to generate `evidence/offline-run.md`.
6. Run `bash scripts/canary_disk_search.sh` to generate `evidence/temp-file-check.md`.
7. Run `python scripts/static_privacy_audit.py`; save the output.
8. Run `pip-audit -r requirements.txt` (while online); save to `evidence/dependency-review.md`.
9. Never write "PASSED" for a check you did not actually run.
